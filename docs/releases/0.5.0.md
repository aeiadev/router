# Router 0.5.0 release notes

Status: released. Router 0.5.0 pairs with Harness 0.5.0. This page describes only scope that was reviewed and accepted. It is not a qualified release claim.

0.5.0 pairs Router and Harness. Router keeps governed routing exclusions in force when accounting fails and provides an opt-in, isolated commands profile; Harness supplies bounded SSH inspection with explicit project policy. Remote interception requires an active, qualified full Harness hook; the commands profile is local and registers no hooks. Offline checks and supplied observations do not establish live host, connector, remote readback or release qualification.

## Accepted Router scope

| Item | What it does |
| --- | --- |
| Receipt input | Receipt file input is bounded to 64 KiB and rejects unsupported special inputs before any event is recorded. |
| Policy under accounting failure | Observable exclusions on governed roles block when the ledger is unavailable; a computed block survives a commit failure; Router-selected models are checked against exclusions. Native and custom agents pass through unchanged. |
| Commands profile lifecycle | `install.sh --profile commands --host claude` or `codex`: reviewed dry-run plan, apply, status, rollback, recover, uninstall, with an isolated launcher and state. |
| Windows and macOS lifecycle fixes | Reversible commands installs on Windows and a canonical macOS lock directory. Windows ACL protection is not qualified. |
| Paired preservation | Tests show the commands profile leaves unrelated bespoke host files and symlinks alone across both install orders. |
| Paired operations workflow | Workflow tests, a fixture test pinned to an exact Harness ref, and `docs/host-validation.md` separating three evidence classes. |

R5 (context and packaging) adds budget, plugin and documentation tests, this page, and the version bump with regenerated plugin metadata. Apart from the launcher fix below, it adds no runtime behavior.

Launcher fix: `pyrun.sh` saves the interpreter it found only after the script exits 0, so a rejected command or a missing script leaves no `python` cache; Python still replaces the launcher.

## Context cost

The default Router catalog (agents, skills and Codex agents) is unchanged from 0.4.1: 56 files, SHA-256 3a2c4a3b3f1f926aade80d07cf041e614d67923bce51b3e9341122a327a9bfd9, pinned by `tests/test_token_budget.py`. No specialist default role and no always-loaded metadata was added, and no hook adds always-on text. `scripts/budget.py --check` reports 1962 B always-on, an estimate of 491 tokens by bytes/4 with no tokenizer. That is an estimate, not measured billing or savings. Explicit commands, warnings and bounded failure diagnostics consume context only when run.

## Test evidence and what has not been run

Full Router and Harness suites ran natively on Linux, macOS and Windows with Python 3.9 and 3.13 (six cells), with 0 failures and every skip named and reviewed. Windows skips the POSIX-only tests and, because 0.2 predates Windows support, the version-skew checks that uninstall the 0.2 tool first or expect a skew notice after a Harness 0.2 install. The macOS and Windows Python 3.9 cells skip the tests that run the 0.1 and 0.2 release installers, which need Python 3.10 or newer. The required SSH integration test ran on Linux only. The PyYAML parity tests ran on Linux with Python 3.9 and 3.13 with PyYAML installed.

The live-host, installed-runtime and paid-pilot qualification gates have not been run. These test runs are not substitutes for them: no real Claude Code or Codex session, connector or model was exercised for this release. Native Windows lifecycle and ACL protection remain unqualified. Historical intermittent ladder resets seen in earlier runs were not replicated or explained; diagnostics are retained.

## Pairing

Router 0.5.0 pairs with Harness 0.5.0, whose CHANGELOG lists its scope. Router never substitutes a current sibling main for the recorded Harness release.
